Pybricks program

          
Uses your current F, P and speed. Paste it into code.pybricks.com and run it on a SPIKE Prime hub with Pybricks installed. Left wheel motor on port A, right on port B.

        

        
      

      

      
The real robot won't use exactly the same numbers. Every robot is a little different: motors, tyres, battery, the mat. Start from the simulator's F and P, then fine-tune on the real robot the same way: F first, then P.

    

  


  

    

      
How F + P drive a robot straight

      

        

          
F · feedforward

          
“How much power do I need to go this fast?”

          
You know the speed you want before the robot moves, so you can set the power ahead of time. That's F: power = F × speed.

          
    
            
  • Too low: the robot crawls, or doesn't move at all. Motors need a little power just to start turning.
    • 
            
  • Too high: it races past the speed you asked for.
    • 
            
  • Tuned: on the speed graph, the blue line sits on the dashed line.
    • 
          

          
F does most of the work, but it can't fix drift. It gives both motors the same power, and no two motors are exactly the same.

        

        

          
P · proportional

          
“I've turned. Steer back, harder the further off I am.”

          
The hub's gyro measures the heading. Error = 0 − heading. P turns that error into steering: one motor gets a little more power, the other a little less.

          
    
            
  • P = 0: the gyro is ignored and the robot drifts.
    • 
            
  • Too small: it steers back slowly and still drifts a few cm.
    • 
            
  • Too big: every correction overshoots. The robot shakes from side to side, and the laser swings back and forth.
    • 
          

        

        

          
I and D · locked

          
I adds up small errors over time to remove a leftover lean. With a good F the lean is tiny. I also builds up while the robot waits at each line, so it lurches when it sets off again.

          
D reacts to how fast the error is changing, which helps stop overshoot in fast turns. When you're driving straight, it mostly magnifies gyro noise.

        

      

      
One trip through the loop (every 10 ms)

      
heading = hub.imu.heading()      # gyro: + means it turned right
error   = 0 - heading            # how far off straight, + means steer right
base    = KF * SPEED             # F: power for the speed we want
correction = KP * error          # P: steer back
left.dc(base + correction)       # left gets more when we steer right
right.dc(base - correction)
wait(10)

      
What you are looking at

      
    
        
  • Orange laser: where the robot is pointing. Green dashes: straight ahead. The orange wedge between them is the heading error.
    • 
        
  • Red line: how far the robot is from the perfect path.
    • 
        
  • See-through robot: a perfect robot at exactly the target speed. If yours falls behind, F is too low.
    • 
        
  • Curved arrow on the hub: which way P is steering, and how hard.
    • 
        
  • Yellow bumps: the same bumps on every run, so you can compare runs fairly.
